この説明書は、測定用ツール(Phase 0)の物です。
{{ app.name }} は、机の上の Android 端末を Windows PC の「手元パネル」にするソフトとして開発中です。この説明書で扱うのは、その設計を決めるために PC と端末の実物を調べる測定用ツール(Probe)だけです。手元パネルのアプリ本体はまだありません。

この説明書のツールは、PC 側が {{ files.zip }}、Android 側が {{ files.apk }} です。どちらも {{ app.repo }} の Releases から手に入ります。

1. はじめに(このツールでできること・できないこと)

測定用ツールは、PC と Android 端末で「どの値が取れるか」「どの操作が通るか」を調べて、結果を画面に出すだけの道具です。PC 側と Android 側の 2 つがあり、別々に動きます(PC と端末をつなぐ必要はありません)。

PC 側で分かること

ツール分かること
audio既定の再生デバイスと、アプリごとの音量・ミュートを読めるか
audio --set指定したアプリの音量を変えて、元に戻せるか
metricsCPU・メモリ・ディスク・ネットワーク・バッテリー・GPU の値を、管理者なしで取れるか。どの取り方がタスク マネージャーに近いか
foregroundいま前面にあるアプリの名前を取れるか。取れないアプリはどれか
keys前面のウィンドウに数字と英字を打ち込めるか
pipe自分だけが読める通り道(名前付きパイプ)を作れるか
SensorHost --probe温度・ファンなどのセンサーを、どの名前で読めるか(管理者で動かす)

Android 側で分かること

ボタン分かること
情報Android の版、機種、カメラの数と向き、カメラが出せる画像の大きさ、振動できるか
振動振動を鳴らせるか
EAN-13 を 10 回商品の箱のバーコード(EAN-13)を、カメラで何秒で読めるか
QR を 3 回QR コードを、カメラで何秒で読めるか

できないこと

  • 手元パネルの機能(ボタンでアプリを開く、音量ミキサー、ダッシュボードなど)はありません。
  • PC と端末をつなぐ機能はありません。
  • 結果をファイルに保存したり、どこかへ送ったりしません。結果は画面に出るだけです。
  • PC や端末の設定は変えません。ただし keys は実際にキーを打ち、audio --set は音量を 2 秒だけ変えて元に戻します。どちらも動かす前に確認があります。

3. 入れ方

PC 側

  1. {{ app.repo }}/releases から {{ files.zip }} をダウンロードします。
  2. ダウンロードした zip を右クリックし、「すべて展開」を選んで展開します。
  3. できた {{ files.folder }} フォルダを開きます。中に DeskSlate.Probe.exe と DeskSlate.SensorHost.exe があります。
  4. フォルダの中の何も無い所を右クリックし、「ターミナルで開く」を選びます。このフォルダで PowerShell が開きます。
  5. 次のように打って Enter を押します。使い方の一覧が出れば、入れ方は終わりです。 
    .\DeskSlate.Probe.exe
インストールはしません。レジストリやスタートメニューにも何も書きません。片付けはフォルダを消すだけです(8 章)。

Android 側(端末だけで入れる)

  1. {{ files.apk }} を端末にコピーします(USB でつないでコピーする、端末のブラウザで Releases から直接ダウンロードする、など)。
  2. 端末のファイルのアプリで APK を開きます。
  3. 「提供元不明のアプリ」を許可するか聞かれたら、許可します。許可の場所は Android の版で違います(7.0 では「設定」→「セキュリティ」、8.0 以降は APK を開いたアプリごとの許可)。
  4. 「インストール」を押します。終わると、ホーム画面かアプリの一覧に「DeskSlate Probe」が出ます。

Android 側(PC から adb で入れる)

端末で USB デバッグを有効にし、PC に adb がある場合だけの方法です。APK を置いたフォルダの PowerShell で次を打ちます。

adb install -r {{ files.apk }}
APK は仮の物です。 デバッグ用の鍵で署名しています。後の版で正式な鍵に変えたら上書きでは入らないので、そのときはこの版を消してから入れ直してください。

4. 使い方

PC 側: 共通

  • どのツールも、3 章で開いた PowerShell(展開したフォルダ)で、.\ から打ちます。
  • コマンドの中の「¥」は、キーボードの「¥」のキー(半角)で打ちます。PowerShell の画面では「＼」の形(バックスラッシュ)に見えることがありますが、同じ文字です。
  • SensorHost 以外は、管理者でない、ふつうの PowerShell で動かします。
  • ツールは終わると自分で止まります。途中でやめたいときは Ctrl + C を押します。
  • 結果は PowerShell の画面に出るだけです。残したいときは、画面の文字を選んでコピーし、メモ帳などに貼ります(公開の場所には貼らないでください。7 章)。

audio(アプリごとの音量の一覧)

  1. 音楽や動画を 1 つ再生しておきます(音を出したことのあるアプリだけが一覧に出ます)。
  2. .\DeskSlate.Probe.exe audio を打ちます。すぐに一覧が出て終わります。

audio --set(音量を 2 秒だけ変える)

  1. 先に audio を動かし、一覧の exe= の後ろの名前(例: example.exe)を確かめます。
  2. .\DeskSlate.Probe.exe audio --set example.exe 30 のように、名前と音量(0〜100)を付けて打ちます。
  3. 「続けますか [y/N]」と聞かれたら、y を打って Enter を押します。ほかのキーならやめます。
  4. そのアプリの音量が 2 秒だけ 30% になり、元に戻ります。音を聞いて、変わって戻ったかを確かめます。

metrics(PC の状態の値)

  1. タスク マネージャー(Ctrl + Shift + Esc)の「パフォーマンス」を開いておきます。
  2. .\DeskSlate.Probe.exe metrics を打ちます。1 秒ごとに 5 回、値が出て終わります。
  3. 出た値と、タスク マネージャーの値を見比べます。

foreground(前面のアプリの名前)

  1. .\DeskSlate.Probe.exe foreground を打ちます。
  2. 30 秒の間に、ほかのウィンドウを何度かクリックして前面を切り替えます。管理者で開いたアプリ(あれば)も 1 回前面にします。
  3. 30 秒たつと「foreground: 終わりました」と出て止まります。

keys(キーの打ち込み)

本当にキーを打ちます。 打つ先は、5 秒後に前面にあるウィンドウです。メモ帳以外を前面にしないでください。
  1. メモ帳を開き、日本語入力をオフ(半角英数)にしておきます。オンのままだと、数字が変換待ちの文字になることがあります。
  2. PowerShell に戻り、.\DeskSlate.Probe.exe keys を打ちます。
  3. 「続けますか [y/N]」と聞かれたら、y を打って Enter を押します。
  4. 「5 4 3 2 1」と数え始めるので、5 秒以内にメモ帳をクリックして前面にします。
  5. メモ帳に 0123456789ABC-123 と入ったかを見ます。メモ帳は保存せずに閉じてかまいません。

pipe(名前付きパイプ)

  1. .\DeskSlate.Probe.exe pipe を打ちます。すぐに結果が出て終わります。何も操作はいりません。

SensorHost --probe(温度とファン)

このツールだけは管理者で動きます。読むだけで、ハードウェアの設定は変えません。
  1. スタートボタンを右クリックし、「ターミナル (管理者)」を選びます。UAC の確認が出たら「はい」を押します。
  2. 展開したフォルダに移ります。フォルダのアドレスバーの文字をコピーし、cd "コピーした場所" と打ちます。
  3. .\DeskSlate.SensorHost.exe --probe を打ちます。数秒で一覧が出て終わります。
  4. 終わったら、管理者の PowerShell は閉じます。

管理者でない PowerShell から動かしても UAC の確認が出て動きますが、結果は別の窓に出て、終わるとすぐ閉じるので読めません。

Android 側: 画面

「DeskSlate Probe」を開くと、上に 4 つのボタン、下に結果が出ます。開いたときに「情報」が 1 回出ます。結果の文字は長押しで選んでコピーできます。

情報・振動

  1. 「情報」を押すと、端末の情報とカメラの一覧が出ます。最後に --- 終わり --- が出ます。
  2. 「振動」を押すと、0.2 秒振動します。振動を感じたかを覚えておきます(画面の文字だけでは、本当に震えたかは分かりません)。

EAN-13 を 10 回(バーコードの読み取り)

1 回ごとに「読む」を押してからバーコードをかざし、読めるまでの時間を測ります。10 回くり返します。

  1. 明るい部屋で、EAN-13 のバーコードが付いた箱を手元に置きます。
  2. 「EAN-13 を 10 回」を押します。初めてのときはカメラを使ってよいか聞かれるので、「許可」を押します。
  3. カメラの映像と「読む(1/10)」のボタンが出ます。この時点では、まだ時間は測っていません。
  4. 「読む(1/10)」を押します。押した瞬間から時間を測り始めます。
  5. すぐに箱をカメラの前にかざし、バーコードが映像の中ではっきり映るようにします。横向きでも縦向きでも読めます。
  6. 読めると、端末が短く振動し、ボタンが「読む(2/10)」に変わります。10 秒たっても読めなければ、その回は「失敗」になり、次の回に進みます。
  7. 箱をいったんカメラの前から外します。外さずに次を押すと、すぐ読めて時間が短く出てしまいます。
  8. 「読む(2/10)」を押してから、また箱をかざします。これを 10 回目までくり返します。
  9. 10 回終わると、結果の行が出て、最後に --- 終わり --- が出ます。カメラの映像とボタンは消えます。
目安: 10 回のうち 8 回以上が、3 秒以内に読めること。結果の最後の行に、満たすかどうかが出ます(5 章)。
読んでいる途中でほかのアプリに移ったり、画面が消えたりすると、そこで止まります。最初からやり直してください。

QR を 3 回

「QR を 3 回」を押し、EAN-13 と同じ手順で 3 回読みます(ボタンは「読む(1/3)」〜「読む(3/3)」)。

adb から動かす場合

PC から adb で動かすこともできます。action には info・vibrate・ean・qr のどれかを入れます。

adb shell am start -n io.github.takosasidev.deskslate.probe/.MainActivity --es action ean
adb logcat -s DeskSlateProbe
adb の ean と qr は、1 回目が自動で始まります。 カメラの準備ができた瞬間に 1 回目の計測が始まるので、先に箱をカメラの前に構えてから命令を打ってください。2 回目からは、画面のボタンと同じく「読む(n/10)」を押してからかざします。画面に出た行は、logcat のタグ DeskSlateProbe にも出ます。

5. 結果の読み方

この章の出力は、形を見せるための例です。アプリ名・機器名・数字は架空の物で、あなたの PC の結果とは違います。

audio

API: NAudio.Wasapi 3.3.0.0
既定の再生デバイス(Render / Multimedia): スピーカー (Example Audio)
全体(AudioEndpointVolume): MasterVolumeLevelScalar=0.40 Mute=False
セッション(AudioSessionManager.Sessions): 2 個
  [0] pid=0 exe=不明 system=True state=AudioSessionStateInactive SimpleAudioVolume.Volume=1.00 Mute=False peak=0.00
  [1] pid=1234 exe=example.exe system=False state=AudioSessionStateActive SimpleAudioVolume.Volume=1.00 Mute=False peak=0.12
audio: 一覧を出しました
  • MasterVolumeLevelScalar は PC 全体の音量(0.40 なら 40%)です。
  • [0] などの行が、音を出しているアプリ 1 つずつです。system=True はシステムの音です。Volume はそのアプリの音量、peak はいま出ている音の大きさです。
  • 行が「失敗: …」になっていたら、そのアプリの音は読めなかったという結果です。

audio --set

API: NAudio.Wasapi 3.3.0.0
example.exe のセッション 1 個の音量を 30% に 2 秒だけ変えて、元に戻します。続けますか [y/N]: y
変えた直後の読み直し: 0.30
戻した後の読み直し: 1.00

「変えた直後」が指定した音量、「戻した後」が元の音量(audio の Volume)と同じなら、変えて戻せています。

ディスク [System.IO.DriveInfo]: C:\ 空き 120.0/500.0 GB
バッテリー [GetSystemPowerStatus]: ACLineStatus=1 BatteryFlag=128 BatteryLifePercent=255 (Flag 128=電池なし, Percent 255=不明)
--- 1 秒
  cpu [GetSystemTimes]: 7.5 %
  cpu [PerfCounter Processor Information\% Processor Utility\_Total]: 9.8 %
  cpu [PerfCounter Processor\% Processor Time\_Total]: 7.2 %
  mem [GlobalMemoryStatusEx]: 使用 9.6/32.0 GB (30 %)
  net [NetworkInterface.GetIPStatistics]: 受信 1.2 kB/s 送信 0.8 kB/s (インターフェース 2 個の合計)
  gpu [PerfCounter GPU Engine\Utilization Percentage, engtype_3D の合計]: 3.1 % (インスタンス 40 個、うち消えた物 0 個)

  (同じ形で 5 秒まで続く)
  • [ ] の中は、値の取り方(API の名前)です。CPU は 3 通りの取り方で出します。タスク マネージャーの CPU の値にいちばん近い行がどれかを見ます。
  • バッテリーの BatteryFlag=128 は電池なし(デスクトップ PC)、BatteryLifePercent=255 は残りが分からない、という意味です。
  • 行が「失敗: …」なら、その取り方はこの PC では使えなかったという結果です。

foreground

API: SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT) + QueryFullProcessImageNameW。今の前面: example-terminal.exe
30 秒の間、ウィンドウを切り替えてください(管理者で開いたアプリも 1 回前面にしてください)。
  2.4 秒  exe=example.exe  pid=1234
  6.1 秒  exe=不明  pid=5678
foreground: 終わりました

前面を切り替えるたびに 1 行出ます。exe=不明 は、そのアプリの名前が取れなかったという意味です。どのアプリで「不明」になったかが、このツールで知りたいことです。

keys

打つ直前の前面: notepad.exe
SendInput が受け取った入力の数: 仮想キー 20/20、Unicode 14/14
  • 「打つ直前の前面」がメモ帳(notepad.exe)なら、打つ先は合っています。
  • 数字が 20/20 と 14/14 なら、Windows はキーを全部受け取っています。
  • 最後はメモ帳を見て確かめます。0123456789ABC-123 と入っていれば成功です。管理者で開いたウィンドウには届かず、そのことは数字からは分かりません。

pipe

API: NamedPipeServerStreamAcl.Create(PipeDirection.Out, PipeSecurity) / NamedPipeClientStream(PipeDirection.In)
作成: OK (名前 DeskSlate.Probe.<SID>、許可は自分の SID の Read だけ)
接続: OK
読めた 1 行: {"probe":"ok"}

最後の行が {"probe":"ok"} なら成功です。途中で「失敗: …」が出たら、その文が結果です。利用者を表す番号(SID)そのものは出しません。

SensorHost --probe

最初の 2 行に、ライブラリの版と、PawnIO(一部のセンサーを読むためのドライバ)が入っているかどうか(IsInstalled=True か False)が出ます。その後に、ハードウェアごとのセンサーの一覧が次の形で続きます。

[ハードウェアの種類] ハードウェアの名前  (識別子)
  センサーの種類 #番号 センサーの名前 = 値  (識別子)

(例)
[Cpu] Example CPU  (…)
  Temperature #0 CPU Package = 45.5  (…)
  Load #0 CPU Total = 7.25  (…)
[Motherboard] Example Board  (…)
  [SuperIO] Example Super I/O  (…)
    Fan #0 Fan #1 = 812  (…)
  • Temperature は温度(℃)、Fan はファンの回転数、Load は負荷(%)です。
  • 値が — の行は、そのセンサーの値が取れなかったという意味です。PawnIO が入っていないと、温度やファンの行が出ない・— になることがあります。

6. 困ったとき

PC 側

症状原因対処
「認識されません」と出る展開したフォルダ以外で打った、または頭の .\ が無い3 章の手順でフォルダを開き直し、.\DeskSlate.Probe.exe の形で打つ
使い方の一覧だけが出るツールの名前のつづりが違う4 章の表のとおり、小文字で打つ

7. 安全とプライバシー

  • 保存しない・外へ通信しない。 PC 側のツールは結果を画面に出すだけで、ファイルに書かず、ネットワークにもつなぎません。Android 側のツールが持つ権限はカメラと振動だけで、インターネットの権限を持たず、何も保存しません。
  • 結果をそのまま公開の場所に貼らない。 PC 側の結果には、動いているアプリの名前、再生デバイスの名前、ドライブの容量、ハードウェアの型番などが入ります。Android 側の結果には、端末の機種と、読んだバーコードの中身が入ります。
  • SensorHost は管理者で動きます。 温度とファンの値を読むだけで、ハードウェアの設定は変えません。終わったら管理者の PowerShell は閉じてください。
  • ドライバは入れません。 一部のセンサーを読むのに使う PawnIO は、使う人が自分で入れる物です。このツールは同梱も導入もしません(入っているかどうかを表示するだけです)。
  • PC を操作するのは 2 つだけ。 keys(キーを打つ)と audio --set(音量を 2 秒だけ変えて戻す)です。どちらも、動かす前に y の確認があります。

8. 片付け

PC 側

  1. 開いている PowerShell を閉じます。
  2. {{ files.folder }} フォルダと、ダウンロードした zip を消します。これで全部です(インストールしていないので、ほかに消す物はありません)。
  3. PawnIO を自分で入れていて、もう要らない場合は、PawnIO の配布元の手順で消します(このツールとは別の物です)。

Android 側

  1. 「設定」→「アプリ」→「DeskSlate Probe」→「アンインストール」で消します。adb があれば、PC から次でも消せます。 
    adb uninstall io.github.takosasidev.deskslate.probe
  2. コピーした APK のファイルが端末に残っていれば、ファイルのアプリで消します。
